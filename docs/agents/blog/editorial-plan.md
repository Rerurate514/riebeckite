# 公式ブログ編集計画

公開対象外の管理ドキュメント。ブログ記事の執筆候補と、その検索意図・想定読者・ドキュメントとの差別化を整理する。

## 役割の分管

- **Docs**（`/docs/`）: 正式な利用方法、設定・APIリファレンス、現在の仕様、体系的な学習。正確さと網羅性を優先し、仕様変更に合わせて更新する。
- **Blog**（`/blog/`）: Riebeckite をまだ知らない人向けの文脈、課題解決、比較、実体験、リリース情報。時間軸のあるコンテンツで、最新性を優先し古くなったら更新またはアーカイブする。

同じ説明を両方に複製せず、ブログ記事から該当ドキュメントへ、ドキュメントから関連記事へ相互リンクする。

## 執筆ルール

- 記事のURLは `docs/blog/<slug>.md` のファイル名で決まる。変更する場合は旧URLに `aliases` frontmatter を残す。
- `docs/blog/` には `README.md`・`index.md` を置かない。ブログ一覧ページは `website/app/routes/blog/index.tsx` が提供しており、`/blog` のコンテンツエントリを増やすと上書きして衝突する（`folderPages({ exclude: ["blog"] })` がフォルダ一覧の干渉を防いでいる）。
- 下書きは `draft: true`。ビルド・一覧・検索・sitemap・RSSから自動で除外される。
- 翻訳は `.ja.md` ペアファイルで作る。翻訳が存在しない記事に無理な言語切替を出さない。
- 架空の計測・根拠のない優位性主張・他OSSへの不当な批判を書かない。比較は検証可能な事実に限る。
- 公開前に、記事が該当ドキュメントへの導線を持っているか確認する。

## 優先順位（2026-11時点）

1. リリース情報（Updates）: 新バージョンが出るたびに1本
2. 「Obsidianのノートを無料でWeb公開する方法」: 検索需要とプロダクトの核が一致
3. 開発思想（Engineering）: 差別化の原理を説明する記事群
4. 比較記事: 事実の揃ったものから順に
