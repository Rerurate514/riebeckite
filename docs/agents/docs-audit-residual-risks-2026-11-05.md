# ドキュメント監査の残存リスク

日付: 2026-11-05
対象: ドキュメント監査ブランチの統合後 `main`
基準コミット: `23e5bd50`
判定: **PARTIAL**

## 結論

既知の P0 / P1 はない。ドキュメント、スキャフォールド、プラグインの非ブロッキング不整合も修正済みで、テストと本番ビルドは通っている。

一方、独立監査を繰り返しても P2 の記述ずれが見つかり続けたため、「独立監査2回連続で新規指摘ゼロ」という READY 条件は満たしていない。残るリスクの中心は、外部サービス実機での未検証と、自動検査が意味的なドキュメントずれを検出できないことにある。

詳細な修正履歴は [自律ドキュメント監査](autonomous-docs-audit-2026-11-05.md) を参照。

## 残存リスク

| 重要度 | リスク | 影響 | 現在の根拠・緩和 |
| --- | --- | --- | --- |
| 高（外部） | Cloudflare Workers の実ログイン、アップロード、Custom Domain の DNS / TLS を実行していない | 初回デプロイやドメイン設定で、ドキュメントどおりに進まない可能性がある | CLI とテンプレートの静的検証、`wrangler.jsonc` の生成確認までは実施済み。実機確認は未実施 |
| 高（外部） | GitHub Actions のシークレット登録、PAT 権限、`repository_dispatch` を実環境で動かしていない | 別リポジトリ構成や自動デプロイが失敗する可能性がある | ワークフローとドキュメントの突合は実施済み。GitHub 上での実行は未検証 |
| 中 | Netlify / Vercel の認証・アップロードを実行していない | 他ホスト向け手順が実環境で通らない可能性がある | アダプターの単体テストと設定検証のみ |
| 中 | 意味的なドキュメントずれを自動検出できない | 将来、CLI フラグ、設定例、API シグネチャ、説明文が実装から再びずれる可能性がある | 現在はリンク、EN/JA 対応、プラグイン README 同期、テーマ同期、アンカー、見出し順のみ自動検査 |
| 中 | 検証は Windows 上で実施 | Linux / macOS や CI でパス・改行・権限まわりが異なる可能性がある | モノレポ全体のテストはローカルで成功。CI 側の再実行は未確認 |
| 低 | Obsidian プラグインの上流挙動を固定していない | 上流の更新で互換性の記述が古くなる可能性がある | 外部リポジトリ依存のため未検証として扱っている |
| 低 | Vite の `esbuild` 設定警告が本番ビルドに残る | ビルドは成功するが、将来の Vite 更新で設定が動かなくなる可能性がある | ドキュメント内容ではなくビルド設定の警告 |
| 低 | 過去の監査記録 (`docs/audits/**`) は履歴として保持 | 古い記述を現在の仕様と誤認する可能性がある | 現在の仕様は `docs/docs/**` と本レポートを参照する |
| 低 | CLI の symlink テスト1件が既存の理由で skip | Windows 環境での symlink 挙動を自動確認できていない | 監査前から存在する skip。今回の変更由来ではない |
| 低 | コミットはローカルのみ | リモート利用者にはまだ反映されない | push は実施していない |

## 未検証の外部挙動

- Cloudflare Workers のログイン、デプロイ、Custom Domain、DNS、TLS、ダッシュボード
- GitHub Actions の実行、リポジトリシークレット、PAT の権限、`repository_dispatch`
- Netlify / Vercel の CLI 認証とアップロード
- npm / pnpm の install-script 承認フロー
- Obsidian 上流プラグインの挙動と互換性マトリクス
- ブラウザの codec、CSP、CSS cascade、アクセシビリティ
- ベンチマークとバンドルサイズの数値
- リポジトリ自身の公開ワークフローの end-to-end 実行

## 推奨する次の作業

1. 信頼できる環境で Cloudflare Workers、GitHub Actions、Netlify、Vercel の実デプロイを各1回実行し、結果を監査記録に残す。
2. CI に CLI フラグ、設定例、コードフェンスの型検査など、意味的なドキュメント検査を追加する。
3. Linux / macOS の CI でモノレポ全体のテストとドキュメントビルドを実行する。
4. Obsidian プラグインの対応バージョンを明記するか、上流のリリースに追従する検査を追加する。
5. Vite の `esbuild` 設定警告を解消する。
