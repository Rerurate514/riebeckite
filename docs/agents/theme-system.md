# Theme Rules for Agents

Themes are presentation-only packages. They may declare a name, options, styles, theme config, and `data-*` attributes; attribute names must begin with `data-`. Use the semantic color, typography, and layout tokens from the Core theme contract rather than application-specific selectors as the public API.

The stable structural hooks include `.rb-theme-root` (the theme root container), `.rb-site`, `.rb-article`, `.rb-article-layout`, `.rb-article-header`, `.rb-article-body`, `.rb-article-content`, and `.rb-article-meta`. `.rb-article-body` is the article body shell that hosts the header, metadata, Markdown, and plugin slots; Markdown typography is scoped to `.rb-article-content`, the wrapper around rendered Markdown that `ArticleBody` emits, so plugin-owned headings are not styled by the Markdown baseline. A plugin or feature exposes a stable root hook named `rr-<feature>` (for example `.rr-search`, `.rr-callout`, `.rr-query`, `.rr-code`) on its outermost rendered element, keeping any historical class on the same element for backward compatibility. Themes target `rb-*` structural hooks and `rr-<feature>` root hooks; BEM element/modifier classes and generic helpers such as `.sr-only` are internal. `rb-*` classes and `--rb-*` tokens are framework-owned; plugin-local tokens use `--rr-*` with `--rb-*` fallbacks. Cascade order is framework structural CSS, base/application structural CSS, plugin defaults, theme CSS, inline config tokens, then `userCss`; the generated `.riebeckite/framework-styles.css` must be imported before `.riebeckite/plugin-styles.css`, which must be imported before `.riebeckite/theme-styles.css`. A theme may go beyond tokens and style the stable hooks directly: put token definitions in `@layer base`, keep visual character rules unlayered so they beat unlayered app/plugin CSS without `!important` (never use `!important`), ship self-hosted Latin webfonts under `styles/fonts/` with their license, and let CJK fall back to system stacks.

Themes must not replace components, inject JSX, add routes/plugins/client scripts, transform DOM, own islands, access the filesystem, or call ContentManager. Put interactive behavior in a plugin/application and visual styling in the theme.

Theme input may be a raw config or a `defineTheme` result. Supported high-level choices are color mode (`light`, `dark`, `system`), typography (`system`, `serif`, `sans`), and article layout (`article`, `sidebar`, `full-width`).

Color mode is a runtime contract. Every theme selector is scoped to the theme root `:is(:root, .rb-theme-root)[data-theme-name="<name>"]`, where `<name>` is the theme's identity name (`riebeckite` for the default theme). On a real site the app sets `data-theme-name` on `<html>`; in a preview, a `class="rb-theme-root" data-theme-name="<name>"` container is the theme root. Light is that selector, dark adds `[data-theme="dark"]`, and system is the `@media (prefers-color-scheme: dark)` block matched by `:not([data-theme])`. Runtime switching sets/removes `data-theme` on `<html>`; an empty attribute breaks the system state. `html.dark` is not part of the contract: the framework never adds a `.dark` class, so dark styling keys on `[data-theme="dark"]` and the system media query only. Interactive switching belongs to a plugin (see `@riebeckite/plugin-color-mode`), never to a theme.
