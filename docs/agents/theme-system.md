# Theme Rules for Agents

Themes are presentation-only packages. They may declare a name, options, styles, theme config, and `data-*` attributes; attribute names must begin with `data-`. Use the semantic color, typography, and layout tokens from the Core theme contract rather than application-specific selectors as the public API.

The stable structural hooks include `.rb-theme-root` (the theme root container), `.rb-site`, `.rb-article`, `.rb-article-layout`, `.rb-article-header`, `.rb-article-body`, `.rb-article-content`, and `.rb-article-meta`. `.rb-article-body` is the article body shell that hosts the header, metadata, Markdown, and plugin components; Markdown typography is scoped to `.rb-article-content`, the wrapper around rendered Markdown that `ArticleBody` emits, so plugin-owned headings are not styled by the Markdown baseline. A new plugin or feature exposes a stable root hook named `rr-<feature>` (for example `.rr-search`, `.rr-callout`, `.rr-query`, `.rr-code`) on its outermost rendered element; some built-in plugins keep documented `rb-*` roots. Plugin output does not include historical class names. Themes target `rb-*` structural hooks and the plugin root hooks documented by each plugin; BEM element/modifier classes and generic helpers such as `.sr-only` are internal. `rb-*` classes and `--rb-*` tokens are framework-owned; plugin-local tokens use `--rr-*` with `--rb-*` fallbacks. For same-origin normal declarations, the CSS contract is `base` → `components` → `utilities` → `rb-plugins` → `rb-theme` → unlayered site CSS. The generated plugin and theme entries import into `rb-plugins` and `rb-theme`, so their internal layers are nested and cannot collide with Tailwind's layers. Import `.riebeckite/framework-styles.css`, `.riebeckite/plugin-styles.css`, and `.riebeckite/theme-styles.css` before site rules. Unlayered site CSS then beats framework, plugin, and theme normal declarations regardless of selector specificity. Theme CSS may style stable hooks directly; use `@layer base` for tokens and normal rules for visual character. This guarantee excludes `!important`, inline styles, animations, transitions, and other cascade origins: important declarations reverse layer order, inline declarations have their own author-origin precedence, animations beat normal declarations, and transitions beat important declarations. Custom properties follow the same cascade and inherit, so inline configuration tokens override stylesheet tokens. A site rule deliberately placed in a named layer receives that layer's priority rather than the unlayered-site guarantee. Themes may ship self-hosted Latin webfonts under `styles/fonts/` with their license; let CJK fall back to system stacks.

Themes must not replace components, inject JSX, add routes/plugins/client scripts, transform DOM, own islands, access the filesystem, or call ContentManager. Put interactive behavior in a plugin/application and visual styling in the theme.

Theme input may be a raw config or a `defineTheme` result. Supported high-level choices are color mode (`light`, `dark`, `system`), typography (`system`, `serif`, `sans`), and article layout (`article`, `sidebar`, `full-width`).

Color mode is a runtime contract. Every theme selector is scoped to the theme root `:is(:root, .rb-theme-root)[data-rb-theme="<name>"]`, where `<name>` is the theme's identity name (`riebeckite` for the default theme). On a real site the app sets `data-rb-theme` on `<html>`; in a preview, a `class="rb-theme-root" data-rb-theme="<name>"` container is the theme root. Light is that selector, dark adds `[data-rb-mode="dark"]`, and system is the `@media (prefers-color-scheme: dark)` block matched by `:not([data-rb-mode])`. Runtime switching sets/removes `data-rb-mode` on `<html>`; an empty attribute breaks the system state. `html.dark` is not part of the contract: the framework never adds a `.dark` class, so dark styling keys on `[data-rb-mode="dark"]` and the system media query only. Interactive switching belongs to a plugin (see `@riebeckite/plugin-color-mode`), never to a theme. A plugin that must branch on dark mode for rendered UI scopes its override to the theme root (`:is(:root, .rb-theme-root)[data-rb-mode="dark"] <hook>`, and `:is(:root, .rb-theme-root):not([data-rb-mode])` inside the system media query) so it applies both at the document root and inside an embedded `.rb-theme-root`; portaled UI appended to `document.body` stays document-global.
