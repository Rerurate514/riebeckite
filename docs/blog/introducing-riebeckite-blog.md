The Riebeckite website has a new section: this blog. Until now, the site covered the framework's usage through [the documentation](/docs/), but there was no place to talk about the project itself — why certain design decisions were made, what is changing between releases, or how people actually use Riebeckite to publish their notes.

## What we will publish

Posts here will fall into a few categories:

- **Updates** — release notes and development news, starting with this post.
- **Engineering** — notes on how Riebeckite is built, such as [how this very blog is assembled](/blog/how-this-blog-is-built/) from the framework's existing pieces.
- **Comparisons** — honest, hands-on comparisons with other static site generators and publishing tools.
- **Tutorials** — practical walkthroughs, like turning an Obsidian vault into a website, that complement rather than duplicate [the documentation](/docs/getting-started/).

The documentation remains the source of truth for how to use Riebeckite. The blog adds the context around it: experience, opinions, and news. When a post touches on setup or configuration in depth, it will link to the relevant documentation page instead of copying it.

## Both in English and Japanese

Riebeckite publishes in English and Japanese, and so will this blog. Posts are translated when it makes sense; when a translation is not available yet, the language switcher simply does not show one. The feed carries everything we publish.

## How to follow along

The site exposes the usual feeds, so you do not need to check back manually:

- [RSS](/feed.xml)
- [Atom](/atom.xml)

We will also tag posts, so if you only care about, say, [announcements](/tags/announcements/), you can follow just that thread.

That is all for today. The next posts are already being drafted — if there is something you would like to read about, open an issue on [GitHub](https://github.com/Rerurate514/riebeckite).
