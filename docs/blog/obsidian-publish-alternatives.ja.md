Obsidian Publish の代替を検索すると、同じ記事が何度も出てきます。「Publish はなぜか高額」という書き出しに始まり、どれも同じように良さそうな無料ツールのリストが続く、あの型です。この記事は、私たちが読みたかったバージョンを試したものです。Riebeckite の公式ブログ上で、Riebeckite も比較対象に含まれるため、以下の事実はすべて2026年11月20日時点で公式ページとリリースノートにあたって確認し、バイアスがかかる箇所は明示してあります。誤りを見つけたら[教えてください](https://github.com/Rerurate514/riebeckite/issues)。訂正します。

## Publish が正解になる場合

たいていの「代替」記事は価格から始まるので、あえて逆から始めます。月10ドル（年払いで月8ドル）の Publish が正解になるのは、たとえばこんな場合です。

- GitHub や Vercel、Netlify のアカウントを作りたくない。コマンドを一度も打ちたくない。
- 自前のインフラなしで、パスワード保護付きの公開が必要。
- サイトを動かし続けるのが Obsidian チームであって、ボランティアの開発者ではないことに意味がある。
- ノートがプレーンな Markdown とコールアウトでできていて、コミュニティプラグインに依存していない。

最後の点が実際の境界線です。[公式の制限事項](https://help.obsidian.md/publish/limitations)によれば、コミュニティプラグインはほぼ動きません。生の Markdown を出すものは例外ですが、プラグインが描画するブロック——まず Dataview——はレンダリングされず、検索もグラフも基本的なものにとどまります。サイトは1サイト4GBまでで、アップロードは1ファイル50MBまで。この制限が問題にならないなら、サブスクはあなたの時間より安くつきます。以下を読んでもお金は節約できません。使いたくない時間を節約できるだけです。

## 2026年11月時点の比較表

| ツール | 型 | ライセンス | 最新リリース | 選択的公開 | コスト |
|---|---|---|---|---|---|
| Obsidian Publish | ホスティングサービス | プロプライエタリ | 現行 | アプリ内でノート単位にチェック | 年払い月8ドル、月払い10ドル |
| Quartz | 静的サイトジェネレーター | MIT | v5.1.0（2026年11月） | リポジトリ単位、すべて出る | 無料 |
| Digital Garden | プラグイン + サイトテンプレート | MIT | 2.103.0（2026年10月） | `dg-publish` フラグ。リンク先は非公開のまま | 無料 |
| Flowershow | ホスティング型プラットフォーム（コアは AGPL） | AGPL-3.0 | 2026年11月 | プラグインで公開するノートを選ぶ | 無料プラン、プレミアム月5ドル |
| Perlite | セルフホストの PHP ビューア | MIT | 1.6.4（2026年10月） | なし。vault 全体を出す | 無料 |
| Webpage Export | HTML 書き出しプラグイン | MIT | 1.9.2（2025年7月） | 書き出し時にファイルを選ぶ | 無料 |
| ObsidianHtml | Python の変換ツール | GPL-3.0 | v3.5.2（2023年5月） | 後述のとおり確認を | 無料 |
| Riebeckite | サイト用フレームワーク（私たちのツール） | Apache-2.0 | 0.1.0（2026年11月） | ノート単位のフラグ、フォルダ除外 | 無料 |

### Quartz

無料ツールの中で最大のコミュニティ（約13,600スター）を持ち、2026年11月にもリリースが出ている、成熟した定番です。vault が git リポジトリになり、TypeScript の設定ファイルと、検索・グラフ・バックリンク（v5 では Bases と Canvas も）付きのサイトが出力されます。引き受けるのは開発者向けの側面です。Node 22、コードとしての設定、そしてメジャーバージョンをまたぐ歴史的に重い移行——v3 のサイトは v4 に移行できず、私たち自身の v4→v5 移行は作り直しに近かった。このトレードの詳細は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)の主題です。

### Digital Garden

選択的に、無料で、公開する方法としては最も簡単です。`dg-publish: true` を付けたノートだけを GitHub リポジトリに push する Obsidian プラグインと、そのリポジトリからビルドされるサイトテンプレート（Eleventy 製、Vercel / Netlify の無料枠で動く）の組み合わせです。リンクされたノードは自動公開されない設計で、プライバシーへの配慮が行き届いています。Publish では描画されないプラグインにも対応しており、README には Dataview（dataviewjs を含む）、Canvas、Bases、Excalidraw 埋め込みが対応済みと書かれています。開発も活発（2026年10月に 2.103.0 をリリース、約2,500スター）。GitHub アカウントすら不要にする管理版 [Forestry.md](https://forestry.md) が、オープンベータで動いています（リリースノートに月間公開ノート数のクオータの記載あり）。

### Flowershow

かつて Next.js テンプレートとして「無料の代替」だったものが、今はホスティング型プラットフォームになったツールです。Obsidian から flowershow.me のサブドメイン（クレジット表記付き）に無料で公開でき、独自ドメインやプレミアム機能は月5ドルから。オープンソースのコアは AGPL-3.0 で、セルフホストも可能です。2026年11月時点で開発は活発。無料の選択肢の中で Publish に一番近い体験ですが、Publish と同じプラットフォーム依存もセットになります。

### Perlite

ジェネレーターではありません。vault フォルダをそのままサーブする PHP アプリケーション（Docker イメージあり）で、リクエストのたびにグラフ、検索、タグ、Mermaid、LaTeX、Canvas をレンダリングします。ビルドステップはありません。この直接性がそのまま制約でもあります。サーブする vault がサイトの全体であり、作者自身の README も「完全に公開してよい vault であること」と `.md` ファイルへの直接アクセスをブロックすることを明記しています。2026年10月のリリースはパッチ適用済みの PHP ベースイメージへの更新でした。メンテナンスが誠実である証拠です。

### Webpage Export

`webpage-html-export` プラグインは、単一ファイル、Canvas、vault 全体を、Obsidian のテーマの見た目を保った HTML に書き出します。検索、ナビゲーションツリー、見出しアウトライン、グラフが出力に組み込まれ、README は Dataview を含む「たいていのプラグイン」の出力に対応と謳っています。出力はただのファイルなので、置き場所を選びません。正直な弱点は、書き出しがパイプラインではないこと（更新のたびに手動でやり直す）と、リリース間隔が空いていること（直近は2025年7月）。育てるガーデンより、アーカイブ向きです。

### ObsidianHtml

ここに載せるのは、今もおすすめ系のまとめ記事に登場するからです。それはまさに、この記事が存在する理由でもあります。最終のタグ付きリリースは2023年5月の v3.5.2 で、リポジトリの最終活動は2025年半ばです（GPL-3.0、Python、ノートを Markdown または HTML サイトに変換）。日付のないまとめ記事がこれを推していたら、その記事の他の部分も同じ目で見てください。

### Riebeckite

私たちのツールなので、制約から書きます。バージョン0.1.0、リリースは2026年11月19日——この表の基準では生まれて1日です。1.0より前のマイナーバージョンには破壊的な変更が入り得るし、コミュニティも小さく、実際に動いているサイトの数もそれ相応です。その上で提供する考え方はこうです。サイトは、Markdown を読み込むただの HonoX / TypeScript アプリケーションであって、設定ファイルが駆動するジェネレーターではない。vault をサイトのリポジトリの外に置ける。ページもコンポーネントも普通のコードである。そしてObsidian 記法（wikilink、埋め込み、コールアウト、インラインタグ）、Dataview クエリ（DQL。dataviewjs は対象外）、検索、バックリンク、グラフ、タグ、英語と日本語の双方の公開を、およそ70のプラグインが npm から入れられる。賛否の議論は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)に別途書きました。

## 誰も値段をつけないリスク: 開発停止

無料ツールはコストで失敗することはめったにありません。開発者が離れたときに失敗します。「Publish の代替」スレッドの下で繰り返される質問が「この開発が止まったらどうなるの」なのは、もっともです。上の ObsidianHtml がまさに実例です。まだ推されており、すでに動いていない。防御策は地味で、効きます。

- 採用前に確認するのは機能表ではなく**最新リリースの日付**。機能は凍っても、リリースは腐ります。
- リポジトリが「存在するか」ではなく、issue に返事がついているか。
- ツールが死んだとき、出力を自分が持っているか。自分のリポジトリに残る静的な HTML や Markdown はツールの死を生き延びます。ホスティング型のプラットフォームや書き出しダイアログはそうなりません。

ライセンスは趣味なら重要ではなく、保険として重要です。MIT や Apache-2.0 なら、開発が止まったときの実際の回収手段であるフォークが摩擦なく作れます。

## 選択的公開と、git 履歴の罠

「一部のノートだけ公開したい」は、もうひとつの定番の質問で、その答えは機能表が示すより差があります。

- **Publish** —— アプリでノートにチェックする。git もファイルも意識しない。
- **Digital Garden / Flowershow** —— ノートにフラグを付ける。Digital Garden はリンクされたノートを自動公開しない。
- **Quartz ほかリポジトリ型** —— リポジトリに入っているものが全部公開されるため、選択的公開はリポジトリ設計の問題になる。vault を非公開リポジトリに置き、公開用リポジトリを別に作る方法は[松浦知也さんが非公開/公開のトレードオフを書き下ろして](https://garden.matsuuratomaya.com/Obsidian%E3%81%A8Quartz%E3%81%A7%E9%83%A8%E5%88%86%E7%9A%84%E3%81%AB%E5%85%AC%E9%96%8B%E3%81%97%E3%81%9F%E3%83%A1%E3%83%A2%E3%82%92%E4%BD%9C%E3%82%8B)おり、 subtree を使った構成は [Oliver Falvai さんが実例を残しています](https://oliverfalvai.com/evergreen/my-quartz-+-obsidian-note-publishing-setup)。
- **Riebeckite** —— ノート単位のフラグ（`private: true`、`draft`）とフォルダ除外。リポジトリ経由で公開する場合の git 履歴の注意は他と同じです。
- **Perlite / Webpage Export** —— 第三者があなたのノートを持つことはありませんが、選択性もありません。前者は vault 全体を出し、後者は明示的に選んだものだけを出します。

リポジトリ型すべてに共通する注意がひとつ。一度でも公開したものは、公開リポジトリの git 履歴に残ります。境界線は初回の公開の前に引いてください。事故の後では遅いです。

## 結局どう選ぶか

- お金: Publish は年96〜120ドル。Flowershow のプレミアムは年60ドルから。それ以外は、代わりに時間を払います。
- 時間: プラグイン方式なら1晩。ジェネレーターなら1晩と、その後ずっと続くアップグレード。プラットフォームなら1時間と、その依存。Publish ならゼロです。
- リスク: ホスティング型は他人のロードマップに、リポジトリ型は自分のメンテナンスに依存します。「動いていないのにおすすめされている（ObsidianHtml）」は、上の表の日付列が防いでくれる状態です。

無料ルートの実際の手順は、[Obsidian のノートを無料で Web 公開する方法](/blog/publish-obsidian-notes-for-free/)にまとめてあります。ジェネレーター選びに絞った議論は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)で。私たちが当事者になる主題なので、そちらは正直に書いたつもりです。
