Obsidian のノートを Web に公開するなら、公式の方法は [Obsidian Publish](https://obsidian.md/publish) です。月10ドル、年払いなら月8ドル。Git もデプロイも関わりたくない人にとって、この値段は割に合っていると思います。完成品ですし、誰かが組み立てて誰かが維持してくれるので。

ただ、この記事はそれ以外の人向けです。無料で公開するルートを、セットアップの手間が軽い順に並べます。最後に、案内系の記事がたいてい飛ばす二つの部分（無料ホスティングの実際の上限と、vault から Web に移すときに壊れるポイント）も書いておきます。ここが意外と大事。

最初にひとつだけ開示しておくと、このブログは私が開発しているフレームワーク Riebeckite 上で動いていて、下のリストにも登場します。並び順はセットアップの手間順であって、推奨順ではありません。

## 1ノートを共有したいだけなら公開は要らない

共有と公開は別の作業です。誰かに1枚のノートを読ませたいだけなら、エクスポートで足ります。Obsidian 標準の Markdown / PDF 出力でもいいですし、[Webpage Export](https://github.com/KosmosisDire/obsidian-webpage-export) の単一ファイル出力なら、テーマの見た目を保った HTML が1枚にまとまります。

公開のほうは、URL を持って育てていくノートのための作業です。この記事はそちらの話をします。

## 月8〜10ドルで買えるもの

Publish はホスティング込みの「1サイト」です。サイトあたり最大4GB、独自ドメイン、CSS と JavaScript でのカスタマイズ、パスワード保護、優先メールサポートまで付いてきます。読者側にはホバープレビュー、グラフ、バックリンク、全文検索も用意されます。

![Obsidian Publish の公式ページ](/assets/blog/obsidian-publish.png)
*publish.obsidian.md のトップページ（2026年11月時点のスクリーンショット）。*

支払う前に読んでおきたいのは[公式の制限事項](https://help.obsidian.md/publish/limitations)です。判断を分けるのはここで、コミュニティプラグインはほぼ動きません。生の Markdown を出すプラグインは例外ですが、Dataview をはじめ、プラグインが出力するブロックはレンダリングされず、検索も基本的なものにとどまります。

ノートが Dataview で組み立てられているなら、お金を払ってもこの問題は解決しません。vault を読めるツールに変える必要があります。この制限だけで、支払う意思があった人の一部は無料ルートに流れることになります。実際、私の周りだけでも話はよく聞きます。

## 一番軽いルート: 公開プラグイン

[Digital Garden](https://github.com/oleeskild/obsidian-digital-garden) は、vault を手放さない設計の Obsidian プラグインです。`dg-publish: true` というプロパティをノートに足して公開ボタンを押すと、フラグを付けたノートだけが GitHub リポジトリに push されます。そこから Vercel / Netlify の無料枠でサイトがビルドされます。[ドキュメント](https://docs.forestry.md/)の手順にはターミナルが登場しません。GitHub アカウントすら不要な管理版 [Forestry.md](https://forestry.md)（オープンベータ）まであります。

設計上の判断が二つ、いい仕事をしています。ひとつは、リンクされているノートを自動公開しないこと。公開ノートが非公開ノートにリンクしていても、そのノートは非公開のままです。もうひとつは、Publish で困られることの多いプラグインへの対応で、README には Dataview（dataviewjs を含む）、Canvas、Bases、Excalidraw 埋め込みが対応済みと書かれています。開発も活発で、2026年10月に 2.103.0 をリリースしていました。

## 定番ルート: 静的サイトジェネレーター Quartz

[Quartz](https://quartz.jzhao.xyz/) は、無料公開の定番になっているツールです。Markdown の vault をそのまま、検索・グラフ・バックリンク・ポップオーバープレビュー・LaTeX・RSS・サイトマップ付きのサイトにしてしまいます。パーサーが Obsidian 記法のために作られていて、wikilink、埋め込み (transclusion)、コールアウト、`![alt|300]` 形式の画像サイズ指定、Mermaid に対応。v5 からは Bases と Canvas まで扱えます。2026年11月に [v5.1.0](https://github.com/jackyzha0/quartz/releases) が出ており、開発は活発です。

![Quartz の公式サイト](/assets/blog/quartz-site.png)
*quartz.jzhao.xyz（2026年11月時点のスクリーンショット）。*

私も前は Quartz 4 でノートを公開していました。なので、引き受ける条件も実感として書いておきます。これは開発者向けツールです。コンテンツは Quartz のリポジトリの中に置き、設定は TypeScript、Node 22 が必要で、ホスティングは自分で用意します（GitHub Pages、Cloudflare Pages、Vercel、Netlify がドキュメント化済み）。

同一メジャーの内側なら `npx quartz update` は本当に滑らかです。ただしメジャーバージョンをまたぐ移行は歴史的に大仕事でした。v4 は v3 を引き継がない書き直しでしたし、私自身の v4→v5 移行は「アップグレード」というより「作り直し」に近い経験でした。この背景は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)で詳しく書いています。設定駆動型ジェネレーターの正直なコストです。

## リポジトリもビルドも不要: Flowershow の無料プラン

Publish に一番近い無料の形は [Flowershow](https://flowershow.app/) だと思います。ホスティング型のプラットフォームで、Obsidian から直接公開できます（ドラッグ & ドロップや CLI にも対応）。無料プランは flowershow.me のサブドメインに、クレジット表記付きのサイトが1つ。独自ドメインは月5ドルのプレミアムから付きます。

![Flowershow の公式サイト](/assets/blog/flowershow.png)
*flowershow.app（2026年11月時点のスクリーンショット）。*

Obsidian 対応（wikilink、Canvas、Bases、Mermaid、LaTeX、グラフ、バックリンク）は本物で、開発は活発、AGPL のコアはセルフホストも可能です。

トレードオフは Publish と同じで、値段が抜けているだけです。プラットフォームは他人のものなので、無料枠の仕様は変わりえます。お試しのデジタルガーデンなら十分。何年も育てるつもりのサイトなら、自分が所有するリポジトリに置くルートを選んだほうがいいです。

## 自前サーバーがあるなら: Perlite

[Perlite](https://github.com/secure-77/Perlite) は問題をひっくり返すツールです。vault をサイトに変換するのではなく、vault をそのままサーブする PHP アプリケーションです（Docker イメージあり）。ビルドステップなしで、グラフ、検索、タグ、Mermaid、LaTeX、Canvas がその場でレンダリングされます。2026年10月のリリースは、パッチ適用済みの PHP ベースイメージへの更新でした。メンテナンスが誠実なのが伝わってきます。

諦めるのは選択的公開です。公開する vault 全体がそのままウェブサイトになります。README も「完全に公開してよい vault であること」と「`.md` ファイルへの直接アクセスをブロックすること」を明記しています。最初から公開前提で vault を作っているなら、自前のハードでこれほど直接的な方法はありません。

## ジェネレーターを使わない: vault を HTML に書き出す

[Webpage Export](https://github.com/KosmosisDire/obsidian-webpage-export)（コミュニティプラグイン webpage-html-export）は、単一ファイル、Canvas、vault 全体を、Obsidian のテーマの見た目を保ったプレーンな HTML に書き出します。検索、ナビゲーションツリー、見出しアウトライン、グラフが組み込み済みで、出力はただのファイルですから、どこに置いても開けます。README は Dataview を含む「たいていのプラグインの出力」に対応と謳っています。

ただ、限界は構造的なものです。書き出しはパイプラインではありません。更新のたびに手で書き出し直すことになりますし、リリースの間隔も空いています（直近は2025年7月）。週で育てるガーデンより、めったに変わらないアーカイブ向きかなと思います。

## 無料の実際のコスト: ホストの上限

無料枠に収まっている間は本当に無料なので、ドキュメントに書かれた数字を挙げておきます。GitHub Pages は公開サイト1GB、帯域は月100GBがソフトリミット、ビルドは毎時10回まで。Vercel / Netlify / Cloudflare Pages の無料枠は個人サイト向けに設計されていて、上限は変動しますが、ノートサイトは遥かに下です。比較のために付けると、Publish はサイトあたり4GBです。

テキストはほとんど占有しません。1ノート10KBなら1,000ノートで10MB程度です。重いのは添付ファイルのほうです。スクリーンショット300枚×0.5MBで150MB、写真を何年も貯めればギガバイト、音声や PDF はさらに先です。個人のサイトなら十分収まりますが、公開というよりバックアップに近い vault を持っているなら、ホスト選びの前にこの計算を一度やっておくのがおすすめです。

## vault から Web へ移すときに壊れるもの

繰り返し現れる3つの破損ポイントを書いておきます。公開の前に直せば安く済んで、後からだと面倒です。

- **`obsidian://` リンク。** アプリ内のノートを開く URI は、ブラウザでは意味を持ちません。上のどのツールも wikilink は変換しますが、本文に `obsidian://` 形式で貼られたリンクは、普通のリンクへの手作業になります。
- **添付ファイルの解決。** 画像参照が生き残るかどうかは、実ファイルの場所とツールの解決方法次第です。wiki 形式の画像埋め込みと vault 全体の添付フォルダは、ツールごとに扱いが違います。大きい移設の前に、画像1枚入りのノート1つを公開して確認するのが最も安い保険です。
- **プラグインが出力するブロック。** Publish は Dataview を描画しません。ジェネレーターと書き出しツールの間で対応と忠実度はまちまちです。ノートの意味が Dataview ブロックの中にあるなら、候補すべてでそのノートを試してください。一つだけでは足りません。

そして、意識的に線を引いておきたい境界がもう1つ。vault の外へ何を出すかです。プラグイン方式はフラグのないノートを push しませんが、一度公開されたものは公開リポジトリの履歴に残ります。線は公開の前に引いてください。後からでは遅いです。

## どれを選ぶか

- ターミナルは使いたくない（できれば GitHub も）なら Digital Garden。あるいは Flowershow、Forestry.md。
- コンテンツ主体の wiki で TypeScript は平気なら Quartz。
- サイトをページやコンポーネントまで自分のものにしたいなら Riebeckite（私のツールです。正直な説明は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)に）。
- すべて公開の vault と自前サーバーなら Perlite。
- 週で育てるガーデンよりアーカイブなら Webpage Export。
- このリストを読むだけで疲れたなら Obsidian Publish。この作業を一度もしなくて済むなら、月8〜10ドルは安い買い物です。

同じ風景をツール別に、メンテナンス状況込みで比較した続編を [Obsidian Publish の代替ツール比較](/blog/obsidian-publish-alternatives/)として用意してあります。無料ツールの現実的なリスクは価格ではなく開発停止なので、続編の表でその点も確認してみてください。

## よくある質問

### Obsidian のノートは無料で公開できますか？

はい。ただし公式サービス経由ではありません。Obsidian Publish は月10ドル（年払いなら月8ドル）で、無料のルートはすべてコミュニティのツール（Digital Garden、Quartz、Flowershow、Perlite、Webpage Export）を通ります。上のリストはセットアップの手間順です。条件を引き受けられそうなものが最初に見つかったら、それがあなたのルートです。

### 無料ホスティングでノートサイトは足りますか？

たいていは足ります。GitHub Pages はサイト1GB・帯域月100GB（ソフトリミット）で、テキストのほうは小さいものです。1,000ノートで約10MB。重いのは添付ファイルで、スクリーンショットを数百枚置く、写真を何年も貯めるなら、ホスト選びの前に一回計算してください。

### Obsidian Publish で Dataview は動きますか？

動きません。公式の制限事項によれば、コミュニティプラグインはほぼ動かず、プラグインが出力するブロック（まず Dataview）はレンダリングされません。Dataview がノートの柱なら、vault を読めるツールで公開することになります。Digital Garden の README は Dataview（dataviewjs を含む）対応を謳っており、Riebeckite は Dataview クエリ（DQL。dataviewjs は対象外）を描画します。

### vault を Web に移すとき、何が壊れますか？

繰り返し壊れるのは3点です。ブラウザでは意味を持たない `obsidian://` 形式のリンク（wikilink はどのツールも変換します）、実ファイルの置き場所しだいで生き残るかどうかが変わる添付ファイルの解決、そしてツールごとに対応が分かれるプラグインブロック。大きい移設の前に、画像1枚入りのノート1つを公開して確認するのが最も安い保険です。
