Obsidian のノートを Web に公開する公式の方法は [Obsidian Publish](https://obsidian.md/publish) で、月10ドル（年払いなら月8ドル）です。Obsidian チームが運営する完成品で、Git もデプロイも聞きたくないなら、この価格は割に合います。この記事はそれ以外の人向けです。無料の公開ルートをセットアップの手間が軽い順に並べて、最後に、案内記事がたいてい飛ばす二つの部分——無料ホスティングの実際の上限と、vault から Web に移すときに壊れるポイント——を書きます。

最初にひとつだけ。このブログは私たちが開発しているフレームワーク Riebeckite 上で動いており、以下のリストにも登場します。並び順はセットアップの手間であって、推奨順ではありません。

## 1ノートを共有したいだけなら、公開は要らない

共有と公開は別の作業です。誰かに1枚のノートを読ませたいだけなら、エクスポートで足ります。Obsidian 標準の Markdown / PDF 出力でもよいですし、[Webpage Export](https://github.com/KosmosisDire/obsidian-webpage-export) の単一ファイル出力なら、テーマの見た目を保った HTML が1枚にまとまります。公開というのは、URL を持って育てていくノートのための作業で、この記事はそれを前提にします。

## 月8〜10ドルで買えるもの

Publish はホスティング込みの「1サイト」です。サイトあたり最大4GB、独自ドメイン、CSS と JavaScript によるカスタマイズ、パスワード保護、優先メールサポートが付きます。読者側にはホバープレビュー、グラフ、バックリンク、全文検索が用意されます。誰かが組み立て、誰かが維持してくれる完成品です。

支払う前に読んでおきたいのは[公式の制限事項](https://help.obsidian.md/publish/limitations)です。判断を分けるのはこの一節——コミュニティプラグインはほぼ動きません。生の Markdown を出すプラグインは例外ですが、Dataview をはじめプラグインが出力するブロックはレンダリングされず、検索も基本的なものにとどまります。ノートが Dataview で組み立てられているなら、お金を払ってもこの問題は解決しません。vault を読めるツールに変える必要があり、この制限だけでも、支払いの意思のある人の一部が無料ルートに流れることになります。

## 一番軽いルート: 公開プラグイン

[Digital Garden](https://github.com/oleeskild/obsidian-digital-garden) は、vault を手放さない設計の Obsidian プラグインです。`dg-publish: true` というプロパティをノートに足して公開ボタンを押すと、フラグを付けたノートだけが GitHub リポジトリに push されます。そこから Vercel / Netlify の無料枠でサイトがビルドされ、[ドキュメント](https://docs.forestry.md/)の手順にはターミナルが登場しません。GitHub アカウントすら不要な管理版 [Forestry.md](https://forestry.md)（オープンベータ）もあります。

設計上の判断が二つ光っています。第一に、リンクされているノートを自動公開しない。公開ノートが非公開ノートにリンクしていても、非公開のままです。第二に、Publish で困られることの多いプラグインに対応している点で、README には Dataview（dataviewjs を含む）、Canvas、Bases、Excalidraw 埋め込みが対応済みと書かれています。開発も活発で、2026年10月に 2.103.0 をリリースしています。

## 定番ルート: 静的サイトジェネレーター Quartz

[Quartz](https://quartz.jzhao.xyz/) は、無料公開の定番になっているツールです。Markdown の vault をそのまま、検索・グラフ・バックリンク・ポップオーバープレビュー・LaTeX・RSS・サイトマップ付きのサイトにします。パーサーが Obsidian 記法のために作られており、wikilink、埋め込み (transclusion)、コールアウト、`![alt|300]` 形式の画像サイズ指定、Mermaid に対応し、v5 からは Bases と Canvas まで扱えます。2026年11月には [v5.1.0](https://github.com/jackyzha0/quartz/releases) が出ており、開発は活発です。

引き受ける条件は「開発者向けツールであること」です。コンテンツは Quartz のリポジトリの中に置き、設定は TypeScript、Node 22 が必要で、ホスティングは自分で用意します（GitHub Pages、Cloudflare Pages、Vercel、Netlify がドキュメント化済み）。同一メジャー内なら `npx quartz update` は本当に滑らかです。ただしメジャーバージョンをまたぐ移行は歴史的に大仕事で、v4 は v3 を引き継がない書き直しでしたし、私たち自身の v4→v5 移行は「アップグレード」というより「作り直し」に近い経験でした。この背景は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)で詳しく書きました。設定駆動型ジェネレーターの正直なコストです。

## リポジトリもビルドも不要: Flowershow の無料プラン

Publish に一番近い無料の形は [Flowershow](https://flowershow.app/) です。ホスティング型のプラットフォームで、Obsidian から直接公開できます（ドラッグ & ドロップや CLI にも対応）。無料プランは flowershow.me のサブドメインに、クレジット表記付きのサイトが1つ。独自ドメインは月5ドルのプレミアムから付きます。Obsidian 対応（wikilink、Canvas、Bases、Mermaid、LaTeX、グラフ、バックリンク）は本物で、開発は活発、AGPL のコアはセルフホストも可能です。

トレードオフは Publish と同じで、値段が抜けているだけです。プラットフォームは他人のものなので、無料枠の仕様は変わりえます。お試しのデジタルガーデンなら十分です。何年も育てるつもりのサイトなら、自分が所有するリポジトリに置くルートを選んでください。

## 自前サーバーがあるなら: Perlite

[Perlite](https://github.com/secure-77/Perlite) は問題をひっくり返します。vault をサイトに変換するのではなく、vault をそのままサーブする PHP アプリケーションです（Docker イメージあり）。ビルドステップなしで、グラフ、検索、タグ、Mermaid、LaTeX、Canvas がその場でレンダリングされます。2026年10月のリリースは、パッチ適用済みの PHP ベースイメージへの更新で、メンテナンスの誠実さを示しています。

諦めるのは選択的公開です。指し先の vault がそのままウェブサイトになります。README も「完全に公開してよい vault であること」`.md` ファイルへの直接アクセスをブロックすること」を明記しています。最初から公開前提の vault なら、自前のハードでこれほど直接的な方法はありません。

## ジェネレーターを使わない: vault を HTML に書き出す

[Webpage Export](https://github.com/KosmosisDire/obsidian-webpage-export)（コミュニティプラグイン webpage-html-export）は、単一ファイル、Canvas、vault 全体を、Obsidian のテーマの見た目を保ったプレーンな HTML に書き出します。検索、ナビゲーションツリー、見出しアウトライン、グラフが組み込み済みで、出力はただのファイルですから、どこに置いても開けます。README は Dataview を含む「たいていのプラグインの出力」に対応と謳っています。

限界は構造的なものです。書き出しはパイプラインではありません。更新のたびに手で書き出し直すことになり、リリースの間隔も空いています（直近は2025年7月）。週で育てるガーデンより、めったに変わらないアーカイブ向きです。

## 無料の実際のコスト: ホストの上限

「無料」は無料枠に収まっている間だけ無料なので、ドキュメントに書かれた数字を挙げておきます。GitHub Pages は公開サイト1GB、帯域は月100GBがソフトリミット、ビルドは毎時10回まで。Vercel / Netlify / Cloudflare Pages の無料枠は個人サイト向けに設計されていて、上限は変動しますが、ノートサイトは遥かに下です。比較のためにつけると、Publish はサイトあたり4GBです。

テキストはほとんど占有しません。1ノート10KBなら1,000ノートで10MB程度です。効いてくるのは添付ファイルです。スクリーンショット300枚×0.5MBで150MB、写真を何年も貯めればギガバイト、音声やPDFはさらに先です。個人のサイトなら十分収まりますが、公開というよりバックアップに近い vault なら、ホスト選択の前にこの計算をしておくべきです。

## vault から Web へ移すときに壊れるもの

繰り返し現れる3つの破損ポイント。公開の前に直せば安く済み、後からだと面倒です。

- **`obsidian://` リンク。** アプリ内のノートを開く URI は、ブラウザでは意味を持ちません。上のどのツールも wikilink は変換しますが、本文に `obsidian://` 形式で貼られたリンクは、普通のリンクへの手作業が必要です。
- **添付ファイルの解決。** 画像参照が生き残るかどうかは、実ファイルの場所とツールの解決方法次第です。wiki 形式の画像埋め込みと vault 全体の添付フォルダは、ツールごとに扱いが違います。大きい移設の前に、画像1枚入りのノート1つを公開して確認するのが最も安い保険です。
- **プラグインが出力するブロック。** Publish は Dataview を描画しません。ジェネレーターと書き出しツールの間で対応と忠実度はまちまちです。ノートの意味が Dataview ブロックの中にあるなら、候補すべてでそのノートを試してください。一つだけでは足りません。

そして、意識的に線を引いておきたい境界がもう1つ。vault の外へ何を出すか。プラグイン方式はフラグのないノートを push しませんが、一度公開されたものは公開リポジトリの履歴に残ります。線は公開の前に引いてください。後からでは遅いです。

## どれを選ぶか

- ターミナルは使いたくない（できれば GitHub も）—— Digital Garden。あるいは Flowershow、Forestry.md。
- コンテンツ主体の wiki で、TypeScript は平気 —— Quartz。
- サイトをページやコンポーネントまで自分のものにしたい —— Riebeckite（私たちのツールです。正直な説明は [Quartz と Riebeckite の違い](/blog/quartz-vs-riebeckite/)に）。
- すべて公開の vault と自前サーバー —— Perlite。
- 週で育てるガーデンよりアーカイブ —— Webpage Export。
- このリストを読むだけで疲れた —— Obsidian Publish。この作業を一度もしなくて済むなら、月8〜10ドルは安い買い物です。

同じ風景をツール別に、メンテナンス状況込みで比較した続編を [Obsidian Publish の代替ツール比較](/blog/obsidian-publish-alternatives/)として用意してあります。無料ツールの現実的なリスクは価格ではなく開発停止なので、続編の表でその点も確認してください。
