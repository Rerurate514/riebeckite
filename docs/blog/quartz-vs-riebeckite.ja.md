検索エンジンから鉱物の話を探してここに来た人へ。riebeckite（曹鉄閃石）はソーダを含む角閃石、quartz（石英）は地殻で2番目に多い鉱物で、確かに割れ方は違います。この記事はその名前を借りた2つのソフトウェア（Obsidian の vault をウェブサイトにする静的サイトジェネレーター [Quartz](https://quartz.jzhao.xyz/) と、私たちが開発しているフレームワーク [Riebeckite](https://riebeckite.dev)）の比較です。

帰属は書くまでもなく、ここは Riebeckite の公式ブログです。だからこそこの記事は分量の多くを Quartz を選ぶ理由と、（バイアスを差し引いても）Quartz が正解になる場所に割いています。誰かがこのページを引用して「これは Quartz ユーザーが書いたものか」と言われる方が、第三者を装った比較よりましだと思っています。

## 同じ問題への2つの答え

2つのプロジェクトはどちらも、Markdown のフォルダ（Obsidian 記法込み）を受け取って、検索・グラフ・バックリンク・wikilink・コールアウト・埋め込み付きのウェブサイトを出力します。どちらも無料で、寛容なライセンスのオープンソース（Quartz は MIT、Riebeckite は Apache-2.0）で、出力は GitHub Pages、Cloudflare Pages、Vercel、Netlify、自前サーバーに置ける素の静的ファイルです。この水準では選択はコイン投げです。

違いは「サイトとは何か」から始まります。

## 設定駆動とコード駆動

**Quartz は設定するジェネレーターです。** コンテンツは Quartz のリポジトリの中に置きます。サイトの組み立て方は設定ファイルで指定し、検索・グラフ・バックリンク・ポップオーバープレビュー・LaTeX・RSS・サイトマップという、膨大な機能セットが手に入ります。Obsidian 記法のパーサーは本物で、v5 では Bases と Canvas まで扱います。組み込みの挙動のままで済むなら、これは表面積の割にたくさんのサイトが手に入る取引です。済まないときの道は Quartz 自身のコンポーネントと拡張の仕組みを通ります。サイトの UI をその流儀でカスタマイズすることになり、私たち自身の Quartz 4 サイト運用で経験したのは、ウェブフレームワークなら普通のページとして書けるものを、Hooks と DOM 操作で書くということでした。[v5.1.0](https://github.com/jackyzha0/quartz/releases) は2026年11月に出ており、プロジェクトは成熟しています。約13,600スター、この分野で最大のコミュニティです。

**Riebeckite は自分が所有するアプリケーションです。** サイトは HonoX + TypeScript のごく普通のプロジェクトで、ルート、コンポーネント、ページが普通の場所にあります。Markdown はそのアプリケーションへの入力の1つで（[「Your content. Your code. Your framework.」](https://riebeckite.dev) が標語です）、vault がサイトのリポジトリの中にある必要すらありません。このブログもアプリの外にあるコンテンツディレクトリから公開しています。npm から入るおよそ70のプラグインが Obsidian 側（wikilink、埋め込み、コールアウト、インラインタグ、Dataview クエリ。DQL が対象で dataviewjs は対象外）と、検索、バックリンク、ローカルグラフ、タグ、hreflang を自動処理する日英二元言語公開をカバーします。プリセット（starter、blog、digital garden、minimal）で走り出して、その先は設定を探すのではなくコードを書きます。

要約すればこうです。Quartz は「どのスイッチを入れますか」と聞き、Riebeckite は「このページは何をすべき？」と聞きます。

## アップグレードの物語

ジェネレーターの本当のコストは数年で払われ、にじみ出るのはメジャーバージョンです。Quartz の歴史は公開されています。v4 は v3 を引き継がない書き直しで、v5 では設定モデルそのものが変わりました。私たち自身の v4→v5 移行は「アップグレード」というより「作り直し」で、Riebeckite が存在するのはこの経験が理由です。同一メジャー内なら `npx quartz update` は本当に滑らかです。メジャーをまたぐと、新しいモデルに合わせて設定を作り直すことになり、蓄積したカスタマイズがその費用を膨らませます。

Riebeckite の同じリスクを正直に書くと、紙の上ではさらに悪い数字になります。バージョンは0.1.0、リリースは2026年11月19日で、1.0より前のマイナーバージョンには破壊的な変更が入るのが前提です。今日の判断基準が安定なら、Quartz が勝ちます。昨日リリースされたばかりのプロジェクトより、10年スケールのロードマップを持つプロジェクトの方が安全です。構造面では、Riebeckite のサイトは最初から普通のアプリケーションコードなので、ジェネレーター固有の設定層を移行するという作業は存在しません。しかし、若い API は構造では救われません。誤った期待で採用いただくより、1.0 でまた会った方がいいと思っています。

## 同じタスクを並べて比較する

- **一部のノートだけを公開する。** Quartz では、リポジトリに入っているものはすべて公開されるため、選択的公開はリポジトリ設計になります（vault を非公開リポジトリに置き、公開範囲を別リポジトリや subtree で運ぶ）。Riebeckite では、ノートにフラグ（`private: true`、`draft`）を付け、フォルダを設定で除外できます。vault は分割も移動もせずに済みます。
- **ノートではないページを作る。** Quartz では Markdown を書き、ジェネレーターが定義するコンポーネントの枠に合わせます。Riebeckite ではルートを書きます。このブログの一覧ページはルートのパターンと言語を判定して投稿を並べる数十行の TSX で、HonoX アプリケーションとしての普通の書き方そのものです。
- **2つの言語で公開する。** Quartz には UI 文言の i18n があります。本文の翻訳は利用者の工夫です。Riebeckite の l10n プラグインは、ファイル名の規約で翻訳をペアにし、サイト全体に hreflang と言語スイッチャーを生やし、未翻訳ページは複製せず公開しません。私たちのように英語と日本語で公開するサイトでは、この非対称が多くを決めました。

## どちらが勝つか

**Quartz** を選んでください、というのはこういうときです。目的がコンテンツ主体の wiki かデジタルガーデンで、組み込みの機能セットで間に合う。最大のコミュニティと、答えの揃った Q&A と、アップグレードのリズムを受け入れられる。これは譲歩の段落ではありません。「vault を公開したい」プロジェクトの過半数において、Quartz は正解です。何年も運用してきた私たちがそう言います。

**Riebeckite** はこういうときです。ノートが何かアプリケーション的なものに流れ込む（独自のページとコンポーネントを持つサイト、ドキュメントシステム、日英二元言語の出版物）で、ジェネレーターの設定面を学ぶより TypeScript を書きたい。vault をサイトのリポジトリの外に、分割せず移動せずに置きたい。その代わりに、トレードにも目をふさいではいけません。生まれて1日の0.1.0のフレームワークはコードを要求しますし、1.0 の前に壊すかもしれません。

一番安いアドバイスは両方を1時間ずつ試すことです。Quartz の `npx quartz create` も、Riebeckite の `npx create-riebeckite` も、数分でサイトを1つ出します。「自分のプロジェクト」に感じられた方は、たいてい次の3回のアップグレードも生き延びます。

プラグイン、ホスティング型プラットフォーム、Obsidian Publish 本体まで含めた比較は [Obsidian Publish の代替ツールを整理して比較する](/blog/obsidian-publish-alternatives/)に、無料公開の実際の手順は [Obsidian のノートを無料で Web 公開する方法](/blog/publish-obsidian-notes-for-free/)にまとめてあります。

## よくある質問

### Quartz と Riebeckite の違いは何ですか？

Quartz は設定するジェネレーターです。コンテンツは Quartz のリポジトリの中に置き、サイトの挙動はその設定とコンポーネントの仕組みで組み立てます。Riebeckite は Markdown を読み込む HonoX + TypeScript のアプリケーションで、ルートもコンポーネントも普通のコードで、vault はサイトのリポジトリの外に置けます。どちらも Obsidian 記法を受け取って、静的ファイルを出力します。

### Riebeckite は無料ですか？

無料です。Apache-2.0 のオープンソースで、ホスティング型の有料プランもありません。ただし現行リリースは0.1.0（2026年11月19日）で、1.0より前のマイナーバージョンには破壊的変更が入り得ます。今日の判断基準が安定性なら、この点は Quartz に軍配が上がります。本文で私たち自身がそう書きました。

### デジタルガーデンにはどちらを選ぶべき？

たいていの「vault を公開したい」プロジェクトでは Quartz です。成熟したツールで、最大のコミュニティがあり、組み込みの機能セットがガーデンをカバーします。Riebeckite が合うのは、サイトがアプリケーションの形をしているとき（独自のページとコンポーネント、2言語での公開、分割も移動もしない vault）で、生まれて1日の0.1.0を引き受ける人です。
