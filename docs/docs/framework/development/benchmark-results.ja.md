# ベンチマーク結果

このページは、各スイートで最後に記録した値をまとめたものです。各節に測定日とコマンドを書いています。ベンチマークは `pnpm test` や CI では実行せず、`benchmarks/results/` の生ファイルもコミットしていません。比較に必要な値だけをここに残します。

個別の注記がない限り、環境は Windows x64、Node.js v24.22.1、AMD Ryzen 7 7730U（16 logical CPU）、14,188 MB RAM です。

## コアビルドパイプライン

2026-11-16 に `pnpm benchmark:vault` で計測しました。生成した realistic な 1,000 ノートの Vault を使い、各シナリオ3回の中央値を出しています。Content キャッシュと出力キャッシュは有効で、編集系のシナリオは初回ビルドの状態を再利用します。

| シナリオ | wall（中央値） | 範囲 | peak RSS |
| --- | ---: | ---: | ---: |
| コールドビルド | 15.9 秒 | 11.6–16.2 秒 | 461 MB |
| 変更なしの warm ビルド | 2.19 秒 | 2.19–2.79 秒 | 466 MB |
| 本文1件の編集 | 2.41 秒 | 2.38–3.05 秒 | 465 MB |
| frontmatter 1件の編集 | 6.09 秒 | 6.05–7.97 秒 | 464 MB |
| ノート1件の追加 | 2.38 秒 | 2.37–3.06 秒 | 470 MB |
| ノート1件の削除 | 2.21 秒 | 2.19–2.84 秒 | 470 MB |

peak RSS はプロセス全体の値です。コールドビルドでは wall 時間の大半をコンテンツの読み込みと処理が占めます。warm と編集系は永続化した Content の状態を再利用します。

## 開発サーバーの起動

### リポジトリの website

2026-11-22 に `pnpm benchmark:development-startup` で計測しました。リポジトリの `website/` を `pnpm dev` で起動し、停止してすぐに再度起動します。各値は1回の測定です。

| 起動 | Vite ready | 初回 HTTP 応答 | 初回表示 |
| --- | ---: | ---: | ---: |
| 1回目 | 10.0 秒 | 26.5 秒 | 26.6 秒 |
| 2回目 | 11.2 秒 | 27.7 秒 | 27.7 秒 |

### 規模別の起動時間

2026-11-17 に `pnpm benchmark:development-startup-scaling` で計測しました。リポジトリの `website/` の設定と plugin 構成を一時サイトへコピーし、deterministic な realistic Vault を生成して、初回起動と直後の2回目起動を記録します。各値は process spawn からの1回の測定値で、単位は秒です。

| Markdown 数 | 初回 Vite ready | 初回 HTTP | 初回表示 | 2回目 Vite ready | 2回目 HTTP | 2回目表示 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 22.11 | 37.46 | 37.53 | 21.98 | 35.24 | 35.25 |
| 100 | 22.23 | 42.93 | 42.96 | 21.23 | 35.99 | 36.01 |
| 1,000 | 21.49 | 62.85 | 62.88 | 21.24 | 37.47 | 37.48 |
| 2,000 | 21.65 | 85.99 | 86.02 | 21.45 | 39.64 | 39.65 |
| 4,000 | 22.38 | 135.32 | 135.35 | 21.80 | 43.41 | 43.43 |
| 5,000 | 21.84 | 156.30 | 156.33 | 21.47 | 43.88 | 43.89 |
| 10,000 | 22.06 | 271.34 | 271.37 | 23.31 | 52.81 | 52.82 |

Vite の起動時間は規模によらずほぼ一定です。2回目は永続化した development route cache により、コンテンツ処理の繰り返しを避けられるため大幅に短くなります。5,000 ファイルでは cache の fingerprint を無制限に読むと `EMFILE` が発生したため、route cache は Content 処理と同じ16並列に読み込みを制限しています。

2026-11-22 に 10,000 ノートで5回追加計測したところ、初回 Vite ready は 78.6–156.1 秒、初回 HTTP 応答は 327.4–543.4 秒、2回目は 17.8–50.3 秒と 37.8–101.6 秒でした。上の表より大幅に遅く、原因は特定できていません。記録済みの基準としては 2026-11-17 の計測を使い、1回の結果だけで判断せず、必要なら再計測してください。

## プリセット SSG

2026-11-07 のマージ後チェックで `pnpm benchmark:presets` を使って計測しました。100 ノートの `starter` プリセットを scaffold し、`no-change` の増分ビルドと、同じソースツリーからの clean SSG を比較しています。記録に残っているのは1シナリオ・1サンプルだけです。

| プリセット | ノート数 | シナリオ | wall | clean wall | peak RSS | 出力キャッシュ | fast path | 等価 |
| --- | ---: | --- | ---: | ---: | ---: | --- | --- | --- |
| starter | 100 | no-change | 14.8 秒 | 26.1 秒 | 1,002 MB | 260 hit / 0 miss | あり | 一致 |

増分ビルドは出力を再描画せず、256 件を再利用しました。wall 時間のうち `outputWrite` が 1.96 秒です。clean ビルドと異なる出力パスはありませんでした。

## SPA ナビゲーション

2026-11-22 に `pnpm benchmark:spa` で計測しました。公開用に pack した tarball を隔離した一時サイトへインストールし、モードごとにコールドビルド5回とブラウザ試行5回を、ローカルの `no-store` サーバー上で実行しています。

| モード | コールドビルド（中央値） | 初回表示 | ナビゲーション | 静的 JS raw / gzip / brotli |
| --- | ---: | ---: | ---: | --- |
| SPA off | 23.4 秒 | 27.2 ms | 30.6 ms | 1.343 MB / 430 KB / 368 KB |
| SPA on、prefetch なし | 23.1 秒 | 25.9 ms | 184.3 ms | 1.355 MB / 434 KB / 371 KB |
| SPA on、hover prefetch | 23.3 秒 | 20.5 ms | 91.7 ms | 1.355 MB / 434 KB / 371 KB |

hover prefetch では、クリック前に5リクエスト、67,365 バイトを取得しました。prefetch なしでは、同じ取得がクリック後に発生します。

## グラフレイアウト

[graph パッケージの README](https://github.com/Rerurate514/riebeckite/blob/main/packages/graph/README.md) に、合成グラフを開発マシンで測った値があります。約 3,600 リンクの 3,000 ノードでは、シミュレーションの収束に約 1.15 秒、1ティックあたり約 3.8 ms です。同じ 3,000 ノードで約 11,900 リンクの高密度グラフでは、60 Hz のフレーム予算を超えるフレームがあります（平均約 12.4 ms、95パーセンタイル約 24 ms）。値はブラウザとマシンに依存します。

## Provenance の記録コスト

生成した 1,000 ノートの Vault で `scripts/benchmark_large_vault.mjs` を実行し、シナリオごとに5回測った中央値です。既定の Content キャッシュと出力キャッシュを有効にしています。環境は Windows（win32）、Node.js v24.22.0 です。

| シナリオ | Provenance off（中央値、範囲） | Provenance on（中央値、範囲） |
| --- | --- | --- |
| コールドビルド | 2,358 ms（2,306–3,119） | 2,422 ms（2,383–2,596） |
| 変更なしの warm ビルド | 584 ms（531–933） | 747 ms（627–2,251） |
| 独立したノート1件の編集 | 646 ms（585–670） | 741 ms（680–1,035） |

Provenance は manifest と出力計画が確定した後に記録します。無効にすると記録と状態のシリアライズがなくなりますが、ビルド出力は変わりません。

## 結果の比較

絶対値はハードウェア、ファイルシステム、バックグラウンドの負荷、fixture の内容に依存します。同じマシン、同じコマンド、同じ fixture で測った結果だけを比較し、1つの数値を製品全体の保証として扱わないでください。ハーネスのコマンドと引数は [`benchmarks/README.md`](https://github.com/Rerurate514/riebeckite/blob/main/benchmarks/README.md) にあります。
