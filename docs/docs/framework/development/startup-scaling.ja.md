# 開発サーバー起動時間の規模別計測

## 方法

`pnpm benchmark:development-startup-scaling` は、リポジトリの `website/` 設定と plugin 構成を一時サイトへコピーする。各件数で homepage を1件含む deterministic な realistic vault を生成し、初回起動、停止、直後の二回目起動を計測する。

ブラウザは計測前に起動する。画像生成の事前処理と Vite サーバー起動を含め、process spawn から次の時点までを測る。

1. Vite が TCP 接続を受け付ける時点
2. 最初のドキュメント HTTP 応答
3. `main#main-content` が表示される時点

既存のユーザーデータと Vite cache は削除しない。削除するのは一時サイトとその cache だけである。各値は1回の測定であり、中央値ではない。このマシン、この設定、この synthetic vault に固有の結果である。

## 結果

環境: Windows x64、Node.js v24.22.1、AMD Ryzen 7 7730U、16 logical CPUs、14,188 MB RAM。

すべて process spawn からの経過秒。

## 所見

二回目起動は永続化した development route cache により大きく短縮される一方、Vite の起動時間はほぼ一定である。大規模 vault では cache の fingerprint 読み込み数を制限する必要がある。5,000件で二回目起動時に無制限の読み込みが `EMFILE` を起こしたため、route cache は既存の content processing と同じ16並列に制限した。
