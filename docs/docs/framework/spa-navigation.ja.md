# SPAナビゲーションの構成

このページでは、SPAナビゲーションを支える構造を、保守する開発者向けに説明します。どのパッケージが関与するか、通常の読み込みとページ移動がどう違うか、ページごとの動作をどう置き換えるかを扱います。有効にする手順は [利用者向けガイド](../guides/spa-navigation.ja.md) を参照してください。

## SPAナビゲーションの全体像

Riebeckite は、サーバーでの描画を基準にします。SPA ナビゲーションは、その仕組みを保ったままブラウザ側だけを強化する拡張です。

- 通常の読み込みでは、ブラウザが HTML 文書を要求し、サーバーがページ全体を返し、[[framework/honox-integration|HonoX]]が island を hydrate します。
- SPA ナビゲーションでは、ブラウザが次の HTML 文書を取得し、ランタイムが main 要素と一致する名前付きシェル region を置き換え、HonoX が新しい island を hydrate します。それ以外のアプリケーションシェルは残ります。

置き換える単位はページのルートであり、HTML 文書全体ではありません。

```mermaid
flowchart LR
    Shell["アプリケーションシェル<br/>ヘッダー / フッター / グローバルUI"]
    Page["ページのルート<br/>main#main-content"]
    Next["次のページのルート"]

    Next -->|"置き換え"| Page
    Shell --- Page
```

## 最小構成

```ts
export default defineConfig({
  site: { title: "My site", baseUrl: "https://example.com" },
  spa: true,
});
```

各ページには安定した `main#main-content` を1つ置く必要があります。Site は、ページに依存するシェルの出力を `data-spa-region="name"` で追加指定できます。ランタイムは、取得した文書に同じ一意な名前の region がある場合だけ、現在の region を置き換えます。region の追加や削除はしないため、相互に SPA 遷移するすべてのルートで同じ region を出力してください。

## 通常の読み込みとSPAナビゲーション

通常の読み込みでは、次の順序で処理が進みます。

1. ブラウザが URL を要求する。
2. サーバーが HTML を描画する。
3. ブラウザが HTML 文書を解析する。
4. HonoX のクライアントが island を hydrate する。
5. アプリケーションとページの初期化処理が実行される。

SPA ナビゲーションでは、次の順序で処理が進みます。

1. ランタイムがクリックを横取りする。
2. ランタイムが対象 URL の HTML を取得する。
3. ランタイムがページスコープを unmount する。
4. ランタイムが head のメタデータを更新する。
5. ランタイムが一致する `data-spa-region` 要素を置き換え、続けて `main#main-content` を置き換える。
6. HonoX の `createClient()` が新しい island を hydrate する。
7. ランタイムが新しいルートにページスコープを mount する。
8. ランタイムが履歴、スクロール位置、フォーカス、通知を更新する。
9. `spa:navigation` イベントが発火する。

順序が重要です。ページの後始末は置き換えの前に、ページの初期化は hydration の後に行います。

## パッケージごとの役割

| パッケージ | 責務 |
| --- | --- |
| `@riebeckite/core` | `spa` 設定の解決、`ClientLifecycle`、スコープ、クリーンアップの取り決め、Plugin の[[glossary/client-entry|クライアントエントリ]]のメタデータを提供する |
| `@riebeckite/honox` | `virtual:riebeckite/client` を生成し、SPA ランタイムを条件付きで読み込み、ページの unmount ・ mount と island の hydration を接続する |
| `@riebeckite/spa` | リンクの横取り、取得、main の置き換え、head の更新、履歴、スクロール、フォーカス、通知、先読みを担当する |
| サイトアプリケーション | 安定したページのルートとアプリケーションシェルを提供し、Plugin コンポーネントの配置とページ依存のシェル出力の region を決める |

SPA パッケージは、HonoX や Plugin の存在を知りません。ランタイムと `createClient()`、`ClientLifecycle` を接続するのは HonoX との連携だけです。

## アプリケーションスコープとページスコープ

`ClientLifecycle` は、初期化処理を2つのスコープに分けます。

| スコープ | ルート | 寿命 | 用途 |
| --- | --- | --- | --- |
| `app` | `document` | 最初のクライアント初期化から破棄まで | ページ移動をまたいで残るシェル UI |
| `page` | `main#main-content` | 1つのページのルート | ページの内容に固有の動作 |

`app` の初期化処理は一度だけ実行されます。`page` の初期化処理は、ページのルートを置き換える前に unmount され、新しいルートに mount し直されます。

初期化処理は、クリーンアップ関数を返せます。`initializerArguments: "context"` を指定すると、`{ root, config, signal, scope }` も受け取れます。`scope` では、イベントリスナー、タイムアウト、インターバル、独自のクリーンアップを登録できます。

unmount は共有スコープの `signal` を先に中断し、登録済みのリソースを破棄してから、クリーンアップの完了を待ちます。初期化とクリーンアップで起きたエラーは個別に記録されるため、1つの失敗でほかの初期化処理は止まりません。

ページの動作は、渡されたルートを基点にしてください。置き換わる DOM の外に作ったリソースは、リソーススコープへ登録するか、返したクリーンアップ関数で解放する必要があります。

## islandの初期化（hydration）

HonoX の `createClient()` は、まだ hydrate していない island を hydrate します。SPA との連携では、新しい main 要素が HTML 文書に挿入された後にこれを呼びます。これにより、新しいページの island は、HTML 文書全体を再読み込みせずに動作します。

`createClient()` は、汎用的な unmount API ではありません。古い main 要素を削除すると、その DOM と DOM に紐づくリスナーは消えますが、HonoX が任意の island の状態を破棄するわけではありません。タイマー、オブザーバー、ネットワークリクエストなど、明示的に解放するものは、ページスコープのクリーンアップで扱います。

## 失敗時のフォールバック

ページ移動を完了できない場合、ランタイムはページ全体の読み込みにフォールバックします。たとえば、次のような場合です。

- 取得に失敗した、または成功以外のステータスが返った
- 取得したレスポンスに `main#main-content` がない
- 現在のページに `main#main-content` がない
- リダイレクト先が現在のオリジンの外である
- main を置き換える前に、ページの後始末や head の更新で例外が起きた
- main を置き換えた後に、コミット処理のフックで例外が起きた

新しいページ移動が始まると、古いページ移動は中断されます。中断されたページ移動はフォールバックせず、新しいページ移動がページを引き継ぎます。

View Transition は任意です。ブラウザが API に対応していない場合や、`prefers-reduced-motion` によって動きの抑制が要求されている場合は、トランジションなしでページ内容を反映します。

## 設計上の制約

- SPA ナビゲーションは、サーバー描画を前提にした段階的な拡張であり、ルーターではありません。各 URL はサーバーが描画します。
- 対象は同一オリジンの GET リンクだけです。フォームとプログラムからのページ移動は対象外です。
- アプリケーションシェルは、`main#main-content` の外側に置く必要があります。
- Plugin コンポーネントは SPA の境界を自分で決めません。サーバー描画の出力が遷移先のページに依存する場合、Site はコンポーネントを `main` または名前付きの `data-spa-region` に置きます。
- 置き換わるシェルの出力を扱うクライアントエントリは、`app` scope で実行し、`spa:navigation` の後に初期化し直すか、イベント委譲を使う必要があります。
- `data-riebeckite-head="page"` を付けた head 要素は置き換えます。`global` と `runtime` を付けた要素は残します。互換性のため、従来のメタデータのセレクタもページ所有として扱います。
- 実行可能な `<script>` は、ページ所有の属性が付いていても置き換えず、再実行しません。所有権を示す属性がない `<script>` と `<style>` は残ります。
- Plugin が生成する[[glossary/head-tag|head タグ]]には、ページ所有の属性が自動で付きます。それ以外の Plugin のページタグは、属性を明示して対象に含めます。
- Plugin のページエントリは、ライフサイクルに合わせる必要があります。渡されたルートを使い、外部のリソースは `scope` に登録するかクリーンアップ関数で解放し、中断用の `signal` を尊重してください。
- SPA を無効にしたビルドは、SPA パッケージを読み込みません。
