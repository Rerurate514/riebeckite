# SPAランタイムの内部実装

このページは、SPAナビゲーションを支えるブラウザ側のランタイムを、保守する開発者向けに説明します。リンクの判定、ページ移動の処理と中断、ページ情報の更新、履歴とスクロール位置の復元、先読み、ページ初期化処理との接続を扱います。ビルドへの影響と現在の検証範囲もまとめます。

パッケージ間の役割分担や設計の全体像は、先に [SPA ナビゲーションの構成](./spa-navigation.ja.md) を読んでください。

## プログレスバー

ランタイムは、body 内の `[data-spa-progress]` 要素と専用のスタイルシートを必要になった時点で1つだけ作成します。ページ移動を開始すると 150ms のタイマーを設定し、キャッシュに当たった高速な遷移でバーが一瞬表示されないようにします。タイマーが発火するまでバーは隠れたままで、ページの確定、document 読み込みへのフォールバック、後続のページ移動による中断、ランタイムの停止のいずれかで消えます。スタイルシートは `--rb-color-accent` があれば使い、なければ組み込みのアクセント色にフォールバックします。動きを減らす設定では、移動するセグメントの代わりに静止したバーを表示します。

## 現在の制約

- リンク処理の対象は、同一オリジンのアンカーと `popstate` に限られます。フォームとプログラムからのページ移動は横取りしません。
- 安定した `main#main-content` が必要です。ルートがない場合は、document 全体の読み込みにフォールバックします。
- 生成される Plugin のメタデータとデータ用スクリプトについては、ページ所有であることが明示されます。それ以外の独自の head 要素は、所有権を示す属性を自分で付ける必要があります。実行可能なスクリプトは常に残り、再実行されません。
- リソーススコープが解放できるのは、そこに登録されたリソースだけです。管理外のリソースには、返り値のクリーンアップ関数が引き続き必要です。
- 先読みのキャッシュは短時間だけ有効で、オフライン用のキャッシュではありません。
- HonoX の `createClient()` は新しい island を hydrate しますが、island を汎用的に破棄する API ではありません。
- SPA ナビゲーションは、オフライン用のキャッシュでもクライアントサイドルーターでもありません。
