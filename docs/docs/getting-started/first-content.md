# First Content

This page shows how to make Markdown appear on your site. You can either edit the samples generated by `starter` or create a new file.

## Where content lives

Generated sites read Markdown from `content/` by default.

```text
my-site/
├─ content/
│  ├─ index.md
│  ├─ guide.en.md
│  ├─ examples.en.md
│  └─ notes/
│     ├─ planning.md
│     └─ writing.md
├─ riebeckite.config.ts
└─ package.json
```

The `starter` preset already creates sample content. You can edit one of those files first; you do not have to create a new page just to verify that editing works.

By default, publishing is explicit: a Markdown file appears on the site only when its frontmatter has `publish: true`.

## Edit an existing sample

Start the local preview if it is not already running:

```sh
npm exec riebeckite dev
```

Open the local URL printed in the terminal. Then edit `content/notes/writing.md` or `content/index.md` and save. When the browser shows your changed text, Markdown editing is working.

## Create the smallest page

Create `content/first-post.md`:

```md
---
title: First post
publish: true
---

Hello from Riebeckite.
```

`title` is the page title. `publish: true` opts the page into the public site. The file name becomes part of the URL: `content/first-post.md` is served at `/first-post`, and index files serve the section root.

You can use regular Markdown. The `starter` preset also includes Obsidian-style Markdown support, so WikiLinks such as `[[planning]]` work with the generated sample notes.

See [Writing content](../guides/writing-content.md) for frontmatter fields, drafts, images, and internal links.

## Build

```sh
npm exec riebeckite build
```

A successful build writes the publishable files to `dist/`.

If a page does not appear, first confirm that the dev server is running, the file is saved, and the frontmatter includes `publish: true`. For deeper investigation, use `inspect content --list` or `doctor` from the [CLI reference](../reference/cli.md).
