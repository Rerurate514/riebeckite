# Localization

Riebeckite の Markdown コンテンツをローカライズするプラグインです。UI 文言の翻訳は担当しませんが、標準の言語切替 UI を提供します。

[English](./l10n.md)

## 基本設定

```ts
import { l10n } from "@riebeckite/plugin-l10n";

l10n({ defaultLang: "ja", languages: ["ja", "en", "zh-CN"] });
```

## ロケール検出と翻訳グループ

ファイル名はこのリポジトリの慣例に合わせ、`README.ja.md` のようにドットで言語を区切る形式を推奨します。`README-ja.md`、`README_ja.md`、`README.en-US.md`、`README.zh-CN.md` も利用できます。ディレクトリ名による検出は行いません。

frontmatter も利用できます。

```md
---
lang: en
translation: getting-started
---
```

併用した場合、組み込みの判定は **frontmatter > 独自検出 > ファイル名 > 既定言語** の優先順位で行われます。言語の矛盾は `L10N_LANGUAGE_CONFLICT`、同じ翻訳 ID と言語の組み合わせの重複は `L10N_DUPLICATE_TRANSLATION` として診断します。`strict: true` ではビルドを失敗させます。

`translation` はロケール検出とは独立しています。異なるパス・ファイル名でも明示的な ID でグループ化できます。

```text
日本語/はじめに.md        lang: ja, translation: getting-started
English/getting-started.md lang: en, translation: getting-started
```

翻訳グループの ID を読み取る frontmatter プロパティは `translationKey` で変更できます。

```ts
l10n({
  defaultLang: "ja",
  languages: ["ja", "en"],
  translationKey: "translationId",
});
```

この場合、`translation: getting-started` の代わりに `translationId: getting-started` を使用します。既定値は `translation` です。

翻訳がない言語向けにページを複製したり生成したりすることはありません。`getLocalization(manifest, slug)` は存在する翻訳だけを `availableLanguages` と言語ごとの `translations` に含め、`getLocalizedContent(manifest, slug, lang)` は見つからなければ `null` を返します。

## URL・テーマ・SEO

既定言語は既存の URL（`/about`）、その他は言語プレフィックス付き（`/en/about`）です。既存のコンテンツロケーション解決を拡張する作りなので、他の URL 解決プラグインとも併用できます。翻訳ごとに URL を変える場合は、異なるソースパスまたは permalink プラグインを使います。

`getLocalization(manifest, slug)` を使うと、現在の言語、存在する言語、各翻訳の href を取得できます。`getLocalizedContent()` は翻訳がなければ `null` を返します。

`l10n(...)` は、標準の記事レイアウトに組み込みの言語切替 UI を追加します。標準の Site consumer がこれを描画するため、l10n 専用の記事レイアウトを実装する必要はありません。実在する翻訳が 2 つ未満のページには表示されません。

## CSS フック

言語切替 UI には `rr-l10n-switcher`、`rr-l10n-switcher__label`、
`rr-l10n-switcher__list`、`rr-l10n-switcher__link` を使用します。既定の CSS はこれらのフックを対象にします。

各ページには、Core の `headTags` 拡張を通じて、実在する翻訳だけを対象にした `hreflang` の alternate link が追加されます。サイトシェルはこれらのタグの描画と、リクエストに応じた `<html lang>` の選択を担当します。WikiLink の Content Graph は同じ言語の翻訳を優先し、なければ元のリンク先を使います。本文では、`@riebeckite/plugin-obsidian-markdown` が Obsidian WikiLink を解決した後に、WikiLink と Markdown の内部リンクを同じ規則で書き換えます。現在のページと同じ言語の翻訳があればその URL に切り替え、なければ元のリンク先を維持します。クエリ文字列とフラグメントは維持し、外部 URL、フラグメントのみのリンク、不明な URL、アセットなどコンテンツ以外の URL は変更しません。リンク依存関係の追跡でも描画と同じ解析済み Markdown URL を使用するため、HTML 文字参照も同じように扱います。Content Graph と本文リンクは同じ解決ポリシーを使います。

## 独自検出

```ts
l10n({
  defaultLang: "ja",
  languages: ["ja", "en", "fr"],
  detect: ({ path }) =>
    path.startsWith("French/") ? { lang: "fr", translationId: "hello" } : undefined,
});
```

独自検出の言語は、frontmatter より優先度が低く、ファイル名より優先度が高くなります。`translationId` は明示的な翻訳グループ ID です。
